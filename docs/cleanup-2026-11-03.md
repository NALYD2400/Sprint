# Tri des fonctionnalités, paramètres et code — 3 novembre 2026

Sprint sert d’abord à retrouver ses projets, lancer leurs serveurs et comprendre leurs erreurs. Le nettoyage privilégie cet usage : garder les actions courantes visibles, ranger les options spécialisées et supprimer les éléments dont l’absence de consommation est vérifiable.

Les paramètres comportent désormais six sections : Apparence, Tableau de bord, Serveurs & logs, Système, Sauvegardes et À propos.

## Nettoyage du code appliqué

- Comparaison des versions et dépôt GitHub partagés entre le contrôle au démarrage et la fenêtre de mise à jour dans `src/services/updates.js`.
- Valeurs par défaut communes au chargement et à la réinitialisation des paramètres frontend ; le repli Rust utilise aussi son implémentation `Default` existante.
- Gestion de la copie, du téléchargement et du timer du skill déplacée dans `AssistantSettings`, qui en est le seul consommateur.
- Suppression du second enregistrement du raccourci au démarrage côté React : le moteur Rust effectue déjà cette opération. Cela enlève aussi un timer et une écriture redondante du raccourci.
- Suppression de `stopAll` côté JavaScript et de la commande native `relaunch_app_cmd`, sans appelant dans le projet. Les actions groupées de la zone de notification et le redémarrage de l’installateur restent implémentés par leurs chemins actifs.
- Suppression de la préférence par défaut `onboardingDismissed`, jamais lue, du nom de terminal stocké sans usage et du setter `setProjects` exposé sans consommateur.
- Suppression du repli HTTP `/api/projects` : aucune route de ce nom n’existe dans cette application Tauri. Les tests utilisent les mocks IPC.
- État initial des métriques aligné sur le payload Rust : retrait des anciennes valeurs disque, pourcentage RAM et uptime qui n’étaient ni alimentées ni affichées.
- Retrait de treize anciennes classes CSS sans référence dans les composants : surfaces, variantes de survol, jauges, grand bouton, badge et anciens conteneurs de logs.
- Aucun timer de fermeture de toast n’est créé lorsque les notifications internes sont désactivées.
- Nettoyage de trois avertissements Clippy dans les tests Rust et retrait d’une exemption `too_many_arguments` devenue inutile.
- Correction du montage de la fixture du test UI : utilisation de la même entrée que les autres scripts, sans réécriture du chemin du module principal. Le rechargement à chaud est désactivé pour cette suite isolée.

## Vérifications et limites du tri

Le graphe des imports des 56 modules JavaScript/JSX présents avant ce passage, y compris les imports différés de l’application principale et du panneau Windows, ne révèle aucun fichier entier orphelin. Les suppressions visent donc des fonctions, champs, styles ou traitements précis. Le nouveau module partagé de mise à jour est utilisé par deux composants.

Les dépendances déclarées sont utilisées par l’application, ses outils de compilation ou les branches natives. Les clés de migration Portly/Sprint et les champs historiques de configuration ne sont pas supprimés : ils servent à relire les configurations existantes. Cette intervention ne réécrit pas les fichiers de configuration personnels.

Ce tri repose sur les références du code et les parcours vérifiés, sans statistiques d’utilisation. Il ne permet pas d’affirmer qu’une fonctionnalité spécialisée n’est jamais utile. Une mesure des performances serait nécessaire avant de modifier les dépendances natives ou de remplacer le moteur de fond.

## Validation

- `npm run lint` : aucun avertissement.
- `npm run build` : compilation de production réussie.
- `npm run test:ui` : 149 contrôles, aucune erreur JavaScript. Comprend les six sections, les options repliées, la copie et le téléchargement du skill déplacé, ainsi que les parcours existants.
- `npm run test:flows` : 48 contrôles des parcours serveur, aucune erreur.
- `npm run test:dashboard` : filtres, favoris au clavier, persistance, récupération et dispositions clair/sombre validés.
- `cargo test --lib` : 22 tests réussis.
- `cargo clippy --lib --tests -- -D warnings` : réussi sans avertissement.
- Inspection des captures À propos en clair et sombre ; les suites existantes vérifient les fenêtres 1320 × 860 et 960 × 620.

Les tests d’interface simulent les commandes IPC : ils ne démarrent ni n’arrêtent les serveurs personnels. Les intégrations réelles Windows (raccourci système, démarrage automatique, notifications, installation d’une mise à jour) ne sont pas déclenchées par ces suites.
